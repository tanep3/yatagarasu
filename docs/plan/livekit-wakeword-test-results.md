# LiveKit WakeWord 実機試験結果

- 実施日: 2026-07-28
- 実施環境: TaneMini、第8世代Core i7、GPUなし
- 音声入力: Tapoカメラ -> go2rtc RTSP、16kHz mono、80msチャンク
- 対象モデル: `models/wakeword/nee_yatagarasu.onnx`
- CPU指標: LinuxプロセスCPU、1論理CPUを100%として算出

## 1. 確定設定

```env
LISTEND_WAKE_THRESHOLD="0.65"
LISTEND_WAKE_EARLY_THRESHOLD="0.15"
LISTEND_WAKE_EARLY_CONSECUTIVE="3"
LISTEND_WAKE_ACTIVE_INTERVAL_SEC="0.08"
LISTEND_WAKE_IDLE_INTERVAL_SEC="1.5"
LISTEND_WAKE_ACTIVITY_RMS_DBFS="-50"
LISTEND_WAKE_SPEECH_HOLD_SEC="2.0"
LISTEND_WAKE_WARMUP_SEC="0.0"
```

実機の正例には`0.1757 -> 0.1611 -> 0.1524`のような低score系列があり、
早期閾値`0.50`では検出できなかった。通常閾値`0.65`と
早期閾値`0.15`の3回連続を実機受入値とした。

## 2. CPU負荷

各測定はservice起動後に60秒ウォームアップし、その後300秒測定した。
listend本体の`/proc/<pid>/stat`に記録されたCPU時間と`/proc/uptime`を使用した。

| 条件 | 平均CPU | ONNX推論回数 | drop | timeout / fatal / reconnect |
|---|---:|---:|---:|---:|
| STT互換、ONNX無効 | 7.34% | 0 | 0 | 0 / 0 / 0 |
| ONNX、80ms scheduler | 15.29% | 399 | 0 | 0 / 0 / 0 |
| ONNX、CPU低減候補 | 11.35% | 179 | 0 | 0 / 0 / 0 |

80ms schedulerの追加CPU使用率は`15.29 - 7.34 = 7.95` percentage pointsで、
目標の5 percentage pointsを満たしていない。
CPU低減候補は4.01ポイントまで抑えたが、実機の正例を取りこぼしたため不採用とした。
CPU測定時の閾値は`0.70 / 0.50`だったが、閾値判定はONNX推論後の定数時間処理であり、
推論間隔が同じ現在設定のCPU負荷を代表できる。誤検出評価には流用しない。

測定環境には生活音があり、STT基準測定中にラジオ由来とみられる文字起こしが
1回発生した。発話2回を含んだ先行基準測定は7.54%だった。両測定の差から
文字起こし負荷を除外すると、実機受入設定のONNX増分はさらに大きくなる可能性がある。
推論回数はheartbeatに記録された測定区間内の差分である。

## 3. 機能受入

| 項目 | 結果 | 確認内容 |
|---|---|---|
| ONNX認識 | 合格 | 所有者による約30回の実発話で30回検出 |
| 即時応答 | 合格 | 「ねぇ、ヤタガラス」後に同梱「はい」を再生 |
| 命令認識 | 合格 | 「はい」後の「右を向いて」を実行 |
| 回り込み防止 | 合格 | 「はい」を命令としてdispatchしない |
| 無指示キャンセル | 合格 | 3秒後に発話せずOFFへ復帰 |
| STT互換 | 合格 | 「マイカメラ、右を向いて」でON遷移し、右移動を実行 |
| 誤検出 | 継続監視 | ラジオ環境で旧設定の誤検出を確認。現在設定の長時間試験は未実施 |

STT互換試験で、日本語読点をCSV区切りとして扱うと
`ねぇ、ヤタガラス`が`ねぇ`と`ヤタガラス`へ分割される問題を検出した。
設定値の区切りをASCIIカンマだけに限定して修正した。

ReazonSpeechは「ねぇ、ヤタガラス」を安定して完全一致へ文字起こしできなかった。
一般文に近い誤認識をエイリアス化すると誤起動を増やすため採用していない。
STT方式は従来ウェイク語を互換用途で使用し、標準の
「ねぇ、ヤタガラス」検出にはONNX方式を使用する。

## 4. 残存確認

確定閾値へ変更した後の連続8時間試験は再実施していない。
通常運用ログで誤検出を継続監視し、発生した場合はscoreと音声環境を記録する。

STT/ONNX切替試験でserviceを繰り返し再起動した後、RTSP接続は継続しているのに
実音声が届かず、ONNX scoreが`0.002`前後へ張り付く事象を確認した。
直接録音にも呼びかけが記録されず、`go2rtc`と`yatagarasu`を順に再起動すると復旧した。
復旧後は実発話2回を2回とも検出した。
